## Encryption

သူငယ်ချင်းဆီ ပို့လိုက်တဲ့ message တစ်စောင်ကို လမ်းတစ်ဝက်မှာ တခြားတစ်ယောက်က ရသွားတယ်လို့ စဉ်းစားကြည့်ပါ။ သာမန်နှုတ်ဆက်စကားဆိုရင် သိပ်ပြဿနာမရှိပေမယ့် ကိုယ်ရေးကိုယ်တာအချက်အလက်တွေ ပါနေရင်တော့ စိတ်ပူစရာပါ။

နေ့စဉ် ပို့နေကြတဲ့ message တွေ၊ online မှာ ဖြည့်သွင်းတဲ့ အချက်အလက်တွေကို ခွင့်မရှိသူတွေ အလွယ်တကူ ဖတ်လို့မရအောင် ဘယ်လိုကာကွယ်ထားကြသလဲ။

ဒီနေရာမှာ Encryption ဆိုတဲ့ နည်းပညာ ပါဝင်လာပါတယ်။ ဒီနေ့တော့ Encryption ရဲ့ အခြေခံသဘောတရားနဲ့ textbook ထဲက စာဝှက်နည်းတွေကို ဥပမာလေးတွေနဲ့ လေ့လာကြည့်ရအောင်။

## What is Encryption?

Encryption ဆိုတာ မူရင်းအချက်အလက်ကို သင့်တော်တဲ့ key မရှိသူအတွက် ဖတ်ရှုနားလည်ဖို့ ခက်ခဲတဲ့ ပုံစံတစ်ခုအဖြစ် ပြောင်းလဲခြင်း ပါ။ မြန်မာလိုတော့ စာဝှက်ခြင်းလို့ ခေါ်နိုင်ပါတယ်။

ဥပမာ ကိုယ်ပို့ချင်တဲ့ စာက STUDY ဖြစ်ပေမယ့် ပို့လိုက်တဲ့အခါ VWXGB ဆိုပြီး ပြောင်းသွားတာမျိုးပါ။ လက်ခံသူက သတ်မှတ်ထားတဲ့ နည်းလမ်းနဲ့ key ကို အသုံးပြုပြီး မူရင်းစာအဖြစ် ပြန်ဖော်ရပါတယ်။

ဒီလို မူရင်းအချက်အလက်အဖြစ် ပြန်ပြောင်းခြင်းကို Decryption (စာဝှက်ပြန်ဖြေခြင်း) လို့ ခေါ်ပါတယ်။

## Why is Encryption important?

ကိုယ့်အချက်အလက်တွေကို ပို့သူနဲ့ လက်ခံသူကြားမှာပဲ လုံခြုံစွာ မျှဝေချင်တာကြောင့်ပါ။ ကိုယ်ရေးကိုယ်တာ message တွေ၊ ငွေပေးချေမှုအချက်အလက်တွေ၊ အဖွဲ့အစည်းတစ်ခုရဲ့ လျှို့ဝှက်ဖိုင်တွေမှာ ဒီလိုကာကွယ်မှု လိုအပ်ပါတယ်။

ဒီနေရာမှာ သိထားသင့်တာတစ်ခု ရှိပါတယ်။ Encryption က data ကို ကြားဖြတ်ရယူလို့ မရအောင် တားဆီးပေးတာလို့ မဆိုလိုပါဘူး။ ကြားဖြတ်ရရှိသွားတဲ့ data ကို သက်ဆိုင်ရာ key မရှိဘဲ နားလည်ဖို့ ခက်ခဲအောင် ကာကွယ်ပေးတာပါ။

ဒါကြောင့် Encryption ရဲ့ အဓိကရည်ရွယ်ချက်ဟာ Confidentiality ကို ကာကွယ်ပေးဖို့ပါ။ ဆိုလိုတာက ခွင့်ပြုထားသူတွေကသာ အချက်အလက်ကို ဖတ်ရှုနားလည်နိုင်ဖို့ ဖြစ်ပါတယ်။

## Three terms to remember

Encryption ကို လေ့လာရင် ဒီစကားလုံးသုံးလုံးနဲ့ အရင်ရင်းနှီးထားရပါမယ်။

Plaintext ဆိုတာ စာမဝှက်ရသေးတဲ့ မူရင်းအချက်အလက်ပါ။

Ciphertext ဆိုတာ စာဝှက်ပြီးနောက် ရရှိလာတဲ့ အချက်အလက်ပါ။

Key ဆိုတာ စာဝှက်ခြင်း၊ စာဝှက်ပြန်ဖြေခြင်းတို့မှာ အသုံးပြုတဲ့ တန်ဖိုးပါ။

Key ဟာ သုံးတဲ့နည်းလမ်းပေါ်မူတည်ပြီး နံပါတ်တစ်ခု၊ keyword တစ်ခု ဒါမှမဟုတ် ပိုရှုပ်ထွေးတဲ့ digital value တစ်ခု ဖြစ်နိုင်ပါတယ်။

A simple example: Caesar Cipher

အစမှာ တွေ့ခဲ့တဲ့ STUDY → VWXGB ကို ပြန်ကြည့်ရအောင်။ ဒီဥပမာမှာ Caesar Cipher ဆိုတဲ့ စာဝှက်နည်းနဲ့ key +3 ကို အသုံးပြုထားပါတယ်။

Caesar Cipher ဟာ အက္ခရာတစ်လုံးချင်းစီကို သတ်မှတ်ထားတဲ့ အရေအတွက်အတိုင်း ရွှေ့ပြီး အစားထိုးတဲ့ နည်းလမ်းပါ။ Key +3 ဆိုရင် အက္ခရာစဉ်အတိုင်း ရှေ့ကို သုံးနေရာရွှေ့ရပါတယ်။

S → T → U → V

T → U → V → W

U → V → W → X

D → E → F → G

Y → Z → A → B

ဒါကြောင့်

Plaintext: STUDY
Key: +3
Ciphertext: VWXGB

Y ကနေ ရွှေ့တဲ့အခါ Z မှာ ရပ်မသွားဘဲ A ကနေ ပြန်ဆက်သွားတာကို သတိပြုပါ။ အက္ခရာစဉ်ရဲ့ အဆုံးကို ကျော်သွားရင် အစကို ပြန်ပတ်ရပါတယ်။

စာဝှက်ပြန်ဖြေချင်ရင်တော့ ပြောင်းပြန်လုပ်ရုံပါပဲ။ VWXGB ထဲက အက္ခရာတစ်လုံးချင်းစီကို နောက်ပြန် သုံးနေရာရွှေ့လိုက်ရင် STUDY ကို ပြန်ရပါမယ်။

Caesar Cipher က နားလည်ရလွယ်ပေမယ့် ဖြစ်နိုင်တဲ့ shift အရေအတွက် နည်းတာကြောင့် တစ်ခုချင်း စမ်းကြည့်ပြီး ဖြေဖို့လည်း လွယ်ပါတယ်။

Textbook ထဲမှာ Caesar Cipher အပြင် Pigpen, Vigenère နဲ့ Rail Fence Cipher တို့ကိုလည်း လေ့လာရပါတယ်။ တစ်ခုချင်းစီက အချက်အလက်ကို ပြောင်းလဲတဲ့ပုံစံ မတူကြပါဘူး။

## Pigpen Cipher

Pigpen Cipher မှာ အက္ခရာတစ်လုံးကို တခြားအက္ခရာတစ်လုံးနဲ့ အစားမထိုးဘဲ သင်္ကေတတစ်ခုနဲ့ အစားထိုးပါတယ်။

အက္ခရာတွေကို grid တွေထဲမှာ နေရာချထားပြီး သက်ဆိုင်ရာအက္ခရာ ရှိနေတဲ့ grid အစိတ်အပိုင်းရဲ့ ပုံသဏ္ဌာန်ကို သင်္ကေတအဖြစ် သုံးပါတယ်။

ဒီလို အစားထိုးသုံးတဲ့ စာဝှက်နည်းမျိုးကို Substitution Cipher လို့ ခေါ်ပါတယ်။ အသုံးပြုထားတဲ့ grid ကို သိရင် သင်္ကေတတစ်ခုချင်းစီကို မူရင်းအက္ခရာအဖြစ် ပြန်ဖော်နိုင်ပါတယ်။

## Vigenère Cipher

Caesar Cipher မှာ အက္ခရာအားလုံးကို shift တစ်ခုတည်းနဲ့ ရွှေ့ခဲ့ပါတယ်။ Vigenère Cipher မှာတော့ keyword တစ်ခုကို အသုံးပြုပြီး အက္ခရာနေရာအလိုက် shift ပြောင်းသုံးပါတယ်။

ဥပမာ message က HELLO ဖြစ်ပြီး keyword က KEY ဆိုပါစို့။ Keyword ကို message နဲ့ အရှည်တူအောင် ထပ်သုံးရပါတယ်။

`
Plaintext: H E L L O
Keystream: K E Y K E
`

အဲဒီနောက် plaintext အက္ခရာနဲ့ သက်ဆိုင်ရာ keystream အက္ခရာကို Vigenère grid ထဲမှာ တွဲဖက်ကြည့်ပြီး ciphertext ကို ရယူပါတယ်။

Shift တစ်ခုတည်း မသုံးတာကြောင့် မူရင်းအက္ခရာတူပေမယ့် စာဝှက်ပြီး ရလာတဲ့ အက္ခရာက မတူနိုင်ပါဘူး။ ဒါက ရိုးရိုး Caesar Cipher ထက် pattern ကို ခန့်မှန်းဖို့ ပိုခက်စေပါတယ်။

## Rail Fence Cipher

Rail Fence Cipher မှာတော့ အက္ခရာတွေကို အခြားအက္ခရာတွေနဲ့ အစားမထိုးပါဘူး။ မူရင်းအက္ခရာတွေရဲ့ နေရာအစီအစဉ်ကို ပြောင်းလိုက်တာပါ။ ဒီနည်းကို Transposition လို့ ခေါ်ပါတယ်။

ဥပမာ LEARN ဆိုတဲ့ စာလုံးကို key 2 နဲ့ စာဝှက်ကြည့်ရအောင်။ အက္ခရာတွေကို တန်းနှစ်တန်းပေါ် အပေါ်၊ အောက် အလှည့်ကျ zigzag ပုံစံနဲ့ ချရေးပါမယ်။

L   A   N
  E   R

ပြီးရင် အပေါ်တန်းကို အရင်ဖတ်ပြီး အောက်တန်းကို ဆက်ဖတ်ပါတယ်။

LAN + ER → LANER

မူရင်း LEARN ထဲက အက္ခရာငါးလုံးလုံး ရှိနေသေးပေမယ့် အစီအစဉ် ပြောင်းသွားတာကို တွေ့ရပါမယ်။ ဒီဥပမာမှာ key 2 ဆိုတာ အသုံးပြုထားတဲ့ တန်းအရေအတွက်ပါ။

ဒီရိုးရာ cipher တွေဟာ Encryption ရဲ့ အခြေခံကို နားလည်ဖို့ အသုံးဝင်ပါတယ်။ ယနေ့ အရေးကြီးတဲ့ digital data တွေကို ကာကွယ်ရာမှာတော့ ပိုမိုရှုပ်ထွေးပြီး လုံခြုံမှုကို စစ်ဆေးထားတဲ့ ခေတ်သစ် encryption နည်းလမ်းတွေကို အသုံးပြုကြပါတယ်။

## Same key or different keys?

Encryption မှာ နောက်ထပ် အဓိကသိထားရမယ့် အကြောင်းအရာက Symmetric နဲ့ Asymmetric Encryption ပါ။

Symmetric Encryption မှာ စာဝှက်ဖို့နဲ့ စာဝှက်ပြန်ဖြေဖို့ key တစ်ခုတည်း ကို အသုံးပြုပါတယ်။

သော့တူတစ်စုံကို လူနှစ်ယောက် ကိုင်ထားသလို စဉ်းစားကြည့်လို့ရပါတယ်။ တစ်ယောက်က သော့ခတ်ပြီး ပို့လိုက်တဲ့အရာကို နောက်တစ်ယောက်က တူညီတဲ့သော့နဲ့ ပြန်ဖွင့်တာမျိုးပါ။ ဒါကြောင့် အဲဒီ key ကို နှစ်ဖက်ကြား လုံခြုံစွာ မျှဝေထားဖို့ လိုပါတယ်။

Asymmetric Encryption မှာတော့ ဆက်နွယ်နေတဲ့ key နှစ်ခု ရှိပါတယ်။

Public Key ဆိုတာ အခြားသူတွေကို မျှဝေပေးနိုင်တဲ့ key ပါ။

Private Key ဆိုတာ ပိုင်ရှင်က လျှို့ဝှက်စွာ ထိန်းသိမ်းထားရတဲ့ key ပါ။

ဥပမာ အောင်က မေ့ဆီ လျှို့ဝှက် message ပို့ချင်တယ်ဆိုပါစို့။

အောင်က မေ့ Public Key ကို သုံးပြီး message ကို encrypt လုပ်ပါတယ်။ ရောက်လာတဲ့ ciphertext ကိုတော့ မေက သူ့ရဲ့ Private Key နဲ့ decrypt လုပ်ပြီး ပြန်ဖတ်ပါတယ်။

ဒီဥပမာမှာ မှတ်ရမယ့်အချက်က လက်ခံသူရဲ့ Public Key နဲ့ စာဝှက်ပြီး၊ လက်ခံသူရဲ့ သက်ဆိုင်ရာ Private Key နဲ့ ပြန်ဖြေခြင်း ပါ။

Encryption ကို နားလည်လာရင် message တစ်စောင် ပို့တာကနေ အရေးကြီးတဲ့ဖိုင်တစ်ခု သိမ်းထားတာအထိ နောက်ကွယ်မှာ အချက်အလက်တွေကို ဘယ်လိုကာကွယ်ပေးထားသလဲဆိုတာ ပိုမြင်လာပါလိမ့်မယ်။

ကိုယ်တိုင် စမ်းကြည့်ချင်ရင်တော့ DATA ဆိုတဲ့ စာလုံးကို Caesar Cipher၊ key +2 နဲ့ စာဝှက်ကြည့်ပါ။ ပြီးရင် ရလာတဲ့ ciphertext ကို နောက်ပြန်ရွှေ့ပြီး မူရင်းစာလုံးကို ပြန်ရသလား စစ်ကြည့်ပါ။
